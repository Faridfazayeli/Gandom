# بررسی و اعمال تصمیم‌های پروژه

این نسخه از مفاهیم و سورس‌های قبلی پروژه تعمیرکار هوشمند استخراج و با تضادهای قبلی یکپارچه شده است.

## تغییرات معماری نهایی
1. محصول از «Repair Intelligence Core» صرفاً فنی به «GANDOM» با بازار خدمات تعمیرات، آگهی، تعمیرکار، کاربر عمومی و هسته AI تبدیل شده است.
2. صفحه Home تبلیغ‌محور است؛ browsing برای مهمان آزاد است.
3. منوی عمومی فقط دو ورودی اصلی دارد: تعمیرکاران و کاربر عمومی.
4. احراز هویت برای پیام و عملیات هویتی در backend enforce شده است.
5. دسترسی تعمیرکار به پنل عملیاتی علاوه بر نقش، پروفایل تأییدشده و اشتراک فعال را بررسی می‌کند.
6. subscription billing و advertisement billing دو موجودیت مستقل هستند.
7. مدت آگهی‌ها به ۱/۷/۳۰/۳۶۵ روز قفل شده و قیمت از دیتابیس مدیریت می‌شود.
8. payment callback idempotent است.
9. آگهی پس از پرداخت به `pending_review` می‌رود و فقط پس از تأیید مدیر فعال می‌شود.
10. مکان برای جستجوی نزدیک‌ترین تعمیرکار از latitude/longitude استفاده می‌کند و در صورت عدم دسترسی مکان، جستجوی شهری باقی می‌ماند.
11. AI هسته rule-based واقعی و deterministic دارد تا بدون فایل مدل باینری نیز build و اجرا شود؛ interface آن برای مدل‌های vision/LLM مستقل نگه داشته شده است.

## مواردی که عمداً حذف شدند
- فایل‌های مدل باینری ساختگی یا ناقص.
- endpointهایی که فقط در توضیحات وجود داشتند ولی منطق اجرایی نداشتند.
- ادعاهای عملکردی مانند mAP یا latency بدون benchmark واقعی.
- secret و credential داخل سورس.
